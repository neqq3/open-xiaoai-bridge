# 音乐频谱灯效（实验功能）

OH2P 1.62.2 可通过 Bridge 为音乐添加彩色频谱。频谱在运行 Bridge 的主机上计算，
音箱通过已有 Client 的 `run_shell`、原厂 `arecord` / `curl` 和 LED 驱动接口显示画面。
无需更新 Client、刷固件、安装设备端二进制或修改 `/data/init.sh`。

本功能与[原厂对话灯效](native-visual.md)共用设备适配和 HTTP 端口，分别控制是否启用。
目前仅支持 OH2P 1.62.2 的原厂音乐播放状态；LX06、其他固件、蓝牙和第三方播放路径
尚未验证，不自动启用。

## 配置

在现有 `config.py` 的 `APP_CONFIG` 中设置：

```python
"native_visual": {
    "enabled": True,  # 收音、等待、回答灯效；只使用音乐灯时可设为 False
    "profile": "auto",
    "public_url": "http://192.168.1.100:9093",  # Bridge 主机的局域网地址
    "music": {
        "enabled": True,
        "brightness": 50,
        "mode": "auto",  # 1、2 或 "auto"
    },
},
```

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `music.enabled` | `False` | 音乐频谱开关，与外层对话灯开关独立 |
| `music.brightness` | `50` | 整数 1～100，控制彩灯最大亮度，不改变音量 |
| `music.mode` | `"auto"` | `1` / `"1"`：双翼频谱；`2` / `"2"`：低音展开；`"auto"`：轮换 |

省略 `music` 时不启动音乐监视任务、不采集播放回环。两种灯效都关闭时不启动灯效端口。
模式和亮度支持配置热重载；修改开关、监听地址或端口后重启 Bridge。

Docker 部署沿用 [docker-compose.native-visual.yml](../docker-compose.native-visual.yml)，
发布 `4399:4399` 和 `9093:9093` 即可；不需要额外的音乐灯端口或 REST API。
已有部署保留自己的后端、环境变量及挂载，只更新为包含本功能的镜像和上述配置。
`public_url` 必须能从音箱访问，不能填写容器内的 `localhost`。端口仅供可信局域网使用。

## 使用与切换

1. 在小爱音箱 App 关闭“音乐播放灯光效果”，避免原厂音乐动画与彩色频谱同时写灯。
2. 播放音乐。检测到受支持的音乐播放状态且原厂灯空闲后，Bridge 自动启动频谱。
3. 暂停音乐后频谱退出；恢复播放后自动重新检查并启动。
4. 唤醒原厂小爱时让出灯带。通过 Bridge 进入对话时，先停止频谱并等待设备清理，
   再进入收音、等待和回答。对话结束且音乐恢复后，频谱自动恢复。

重新打开 App 的原厂音乐灯开关时，本功能让路，不替用户更改该设置。
不要同时运行独立的 `xiaomi-sound-spectrum` 服务和本功能；检测到其 OH2P 服务目录时
不会启动 Bridge 频谱。关闭 `music.enabled` 并重启 Bridge 即可停用。

## 显示方式

效果移植自 [xiaomi-sound-spectrum](spectrum-attribution.md)，保留左右声道独立的
八频段分析、整数增益与平滑算法，以及原配色和白色高亮：

- **模式 1**：左右频谱分区显示，强能量混入白色；低音鼓点和高频瞬态有独立提示。
- **模式 2**：低音推动亮区从中央向两侧展开，回落时收缩；保留白色峰值与随频谱变化的配色。
- **auto**：每处理 2800 个活动音频块切换一次，不把它标成固定一分钟；实际周期取决于回环出数速度。

复用 OH2P 的 18→12 面积重采样：每个虚拟像素均有贡献，低音端落在前排中央，
高频端分布到两端。正对音箱时物理 0 号在右端、11 号在左端。

同一批人工 PCM 下，两个模式及轮换的逐帧颜色已与原 C 算法对照。网络输出最多约
20 帧/秒，实际显示节奏可能与设备内直接运行不同，不承诺任何音乐下肉眼完全一致。
传输续开会保留算法状态，不会每 120 秒重置自动轮换。

暂停音乐仍按 Bridge 生命周期直接退出，不驻留以展示独立程序的微光待机过程。
名义采集格式为 48 kHz / 双声道 / S16_LE，沿用原算法频点定义；尚未做物理频率校准。

## 运行边界

音频回环只用于本机 Bridge 的频谱计算，内存中按 1024 帧处理，不写音频文件；
颜色输出最多约 20 帧/秒，仅保留最新帧。上传与下载使用各自单连接的随机短期令牌，
不提供任意命令执行接口。实际刷新率会受到音箱、网络和主机负载影响。

每次设备任务最长 120 秒，结束后仍在播放则重新检查并续开；交接可能有短暂间隔。
设备端另有独立期限和断流退出，停止时只清理该任务创建的进程、FIFO 和锁目录。
不停止原厂 LED 服务，也不全局结束 `arecord`。RPC 完成结果不明时，停止新增灯效
尝试直到重启 Bridge，语音流程仍可运行。强制杀死设备脚本导致残留锁时，应先确认
旧任务已退出再处理，不能为重试而直接绕过锁。

原厂状态检查不是独占锁，不能保证任意并发情况下完全无瞬时覆盖。本功能默认关闭，
正式使用前应验证音乐播放、原厂唤醒、Bridge 连续对话和断线恢复。

## 开发验证

```bash
python -m unittest discover -s tests -p 'test*visual*.py' -v
python -m unittest discover -s tests -p 'test_spectrum_effects.py' -v
```

Linux 环境会额外执行设备脚本状态检查；单元测试不能替代真实灯带、播放声音和
原厂接管的观察。
